## Bounded future checks and remaining acceptance

For a small Crescent editor change, run the focused numerical files and the
maintained N128 pilot instead of rerunning every shape's full matrix:

```powershell
node --test src/surfaces/crescent.test.ts src/surfaces/crescent-distance.test.ts src/terrain/crescent-brush.test.ts src/persistence/crescent-format.test.ts src/rendering/crescent-view.test.ts
node node_modules/@playwright/test/cli.js test --config playwright.crescent.config.mjs tests/crescent-pilot.spec.ts
```

Use `playwright.crescent-regression.config.mjs` for the maintained ten-case
shared-system selection, and `playwright.crescent-touch.config.mjs` for phone
emulation. Run the changed geometry/rendering/input subset when those mechanisms
change; material architecture changes require the full relevant qualification.
All browser recipes use the task preview on port 5278, installed Chrome, one
worker and no retries. Keep expensive measurements sequential and BelowNormal.

Owner acceptance remains separate: review the real silhouette/proportions and
tips, ordinary painting on all surfaces, camera/map controls and Save/Open on
the intended devices. Physical touch/stylus hardware is still an acceptance item.
The supported body is the actual fixed faceted model; extreme unsupported
proportions, continuous smooth meshes, displaced terrain, illustrated mapping,
hollow Crescent, holes, tunnels, links and later shapes remain deferred.

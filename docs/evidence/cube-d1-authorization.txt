# CUBE-D1 — FIRST VISUAL PHYSICAL CUBE

## Objective

Create the first genuine visual rendering of our solid cube world using the accepted Cube-A through Cube-C2B2 numerical foundation.

Deliver a **read-only, owner-inspectable development preview** containing:

1. A true three-dimensional physical cube view.
2. An unfolded, topologically connected two-dimensional six-face map.

Both views must display the same authoritative terrain.

This is the beginning of Cube-D visual rendering, not the full Cube-E interactive sculpting editor.

## 1. Real physical cube appearance

Render the actual solid-cube reference geometry:

- Six truly planar square faces.
- Twelve connected physical edges.
- Eight shared corners.
- Correct 90-degree physical dihedral angles.
- Exact face orientations and connections.
- No sphere or rounded-cube substitute.
- No disconnected six-map illusion.

The reference cube must visibly look like a cube.

Do not distort the geometry merely to hide terrain-rendering seams.

## 2. Elevation-first rendering

Use the accepted canonical Cube-A Float32 terrain authority as the only source of geography.

Render:

- Oceans and sea-level boundaries.
- Coastlines.
- Land elevation.
- Mountain ranges.
- Valleys and depressions.
- Readable shaded relief.
- Signed positive and negative elevations.

The same geographic feature crossing a physical edge must remain continuous and correctly positioned on both adjoining faces.

Elevation and physical gradients must respect real neighboring samples across edges and corners.

Do not blend cube face normals into a fictional smooth sphere.

At this stage, shaded relief represents elevation visually. Actual elevation-displaced 3D terrain geometry remains a separately planned advanced capability.

## 3. Two coordinated viewing modes

### Three-dimensional cube

Provide a development inspection view that allows the owner to:

- Orbit/rotate the cube.
- Zoom in and out.
- Recenter the view.
- Examine all six faces.
- Inspect shared edges and corners.
- View the same geography from multiple angles.

Controls may be simple and development-only.

### Two-dimensional unfolded cube

Render six correctly oriented square panels in a documented connected cube net.

Preserve correct face labels, orientation and physical adjacency.

The net is a visual arrangement, not six independent elevation maps.

Both views must show corresponding geographic features at matching locations.

Do not implement full terrain editing through either view during D1.

## 4. GPU rendering and CPU fallback

Use browser-side rendering.

Prefer our established WebGL2/GPU rendering patterns where suitable, with an independently functional CPU fallback.

Requirements:

- No server GPU.
- No paid rendering service.
- No unnecessary server processing.
- Revision-aware terrain preparation.
- Bounded texture and CPU-buffer allocations.
- Responsive camera movement.
- Correct initialization, resize and disposal.
- Explicit WebGL failure and context-loss behavior.
- Recovery without geography changes.

The CPU fallback must display the same underlying terrain, not placeholder geography.

Document rendering differences and justified rasterization tolerances.

## 5. First visual quality standards

We're aiming for polished professional cartographic presentation.

Use sensible defaults for land, water, elevation shading and lighting.

The result should be pleasant and geographically readable, not a retro sprite-based video-game map.

This is not authorization to build the full professional illustration/asset system of master Phase 5.

Do not introduce huge art libraries, city stamps, dungeon assets or unrelated procedural generators in D1.

## 6. Owner-inspectable development preview

This is especially important.

Provide an isolated preview reachable through the standalone development application.

Seed it with representative geography showing coastlines, elevation transitions, mountains and features crossing real cube edges.

Allow viewing at N128 and N256.

Document clear, simple instructions for the owner to open it and visually inspect the result.

The preview must be read-only and clearly identified as a development demonstration.

Do not expose a partially completed cube as a normal New World option or modify the live website.

## 7. Verification and screenshots

Create numerical and browser tests covering:

- All six faces.
- All twelve edges.
- All eight corners.
- Matching terrain on both sides of an edge.
- Matching 3D and unfolded geography.
- N128 and N256.
- Sea-level boundaries and signed elevations.
- Camera rotation and zoom.
- Resize and viewport recovery.
- WebGL2 and forced CPU fallback.
- Context loss, initialization errors and cleanup.
- Canonical terrain authority preservation.
- No changes to source words or revisions during viewing.

Deliver actual screenshots from the running browser preview.

Include front, opposite, edge and corner viewpoints, along with the complete unfolded cube.

Verify consistent real geography between the two views.

Do not confuse screenshots of numerical test fixtures with screenshots of the new visible cube.

## 8. Performance requirements

Measure actual rendering behavior on desktop and mobile-emulated browser profiles.

Separate:

- Initialization.
- First visible terrain pixels.
- Complete initial render.
- Camera interaction and frame gaps.
- N128/N256 terrain preparation.
- Revision/update costs.
- GPU/CPU fallback behavior.
- Retained buffers and process memory.
- Context-loss recovery.

Do not repeat the sphere's first-visible-latency mistake.

Faster overall preparation is not sufficient if the user waits longer to see geography.

Test meaningful low-performance conditions and report limitations.

Do not claim physical-phone acceptance unless a physical device is actually tested.

Do not modify the existing 65,536-word gesture-history ceiling.

Preserve all accepted sphere, cylinder, bounded and wrapped editors and v1–v4 saved data.

Keep existing World/surface/terrain ownership and version contracts.

No original Serrian Tide website, existing Worlds, databases, Docker, hosting or Production changes.

Work exclusively in:

`Revty79/serrian-tide-world`

Preserve our eleven master phases and approved geometry order.

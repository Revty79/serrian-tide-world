# Unified Atlas workspace — F1 through A7-D

Atlas starts with a shape chooser before allocating terrain. Bounded flat maps, horizontally wrapped flat maps, spherical worlds and physical capped cylinders use the same document controls, overlay toolbar, tool picker, library, saved/modified status and browser fullscreen action. Horizontal periodic geography is explicitly distinguished from a complete physical cylinder. Sphere creation requires a positive finite radius in meters and N=128 or N=256. There are no functional placeholders for future shapes.

## Document and view ownership

`editor/atlas-document.ts` defines a discriminated host document. A planar document retains its original `TerrainDocument` and history; a sphere retains the original prepared `SphericalSession`, canonical authority and derived display cache. `App` owns **one active document**, not a planar editor hidden underneath a sphere. Preparing a replacement temporarily retains the old document and candidate until successful acceptance; that is deliberate recovery memory, not duplicate authoritative terrain for one world.

`WorkspaceChrome` is the common interface. The planar provider uses `TerrainCanvas`; the embedded spherical provider uses the existing `SphericalViewport` render/input loop. Its optional workspace slot supplies contextual controls, geodesic brush parameters, projection actions, readouts and history availability. The same chrome renders those slots. Providers own view/camera state; changing Globe/Net or Focus/Fill/Fit never changes authority, dimensions, identities or elevations. There is no universal rectangular preview layout: future providers must supply their surface's connected geography, inverses, footprints, eligible surfaces and navigation.

The terrain, topology, physical metric, brush, smoothing, history, projection and persistence algorithms are retained. A small optional `hideToolPicker` parameter lets the existing planar brush panel use the shared picker without duplicating buttons. Standalone spherical preview/editor hosts remain available to test fixtures. They are not imported by the product entry or offered as launchers in Atlas.

## Safe operations

Save finishes pointer input and drains accepted queued spherical or cylindrical work before taking its versioned snapshot. The existing adapter validates and atomically commits heightmap/catalog together. The host marks the checkpoint only after commit. A failed operation reports its error while retaining the real modified/saved state, terrain, name, history and prior committed record. A post-commit catalog refresh failure is reported separately; it does not undo a successful checkpoint.

Open completely validates the v1/v2/v3/v4 candidate, prepares spherical display caches where needed, then asks before discarding unsaved work and replaces the document. Canceling the prompt or a failed read/validation/preparation leaves the old authority, camera and history in place. Successful reopening intentionally starts fresh camera/history, as in A6-E. New creates a new identity and blank ocean; its shape choice is never a conversion. Canceling cooperative preparation invalidates the pending operation token; a stale completion cannot replace a later document. Busy controls and the synchronous host/session locks prevent concurrent mutations and operations. Browser unload guards remain in the shared host. No persistence format, IndexedDB version or existing catalog row is migrated.

The mixed catalog labels typed records as Bounded plane, Wrapped plane, Sphere or Physical cylinder. Preexisting untyped entries remain Planar (legacy): guessing geometry from a catalog without reading and validating its payload would misrepresent it. Open dispatches on the validated record rather than the catalog label. All saves remain browser/profile/origin/device local, with explicit warnings and no autosave, backend, synchronization or physical-device durability claim.

## Interface and accessibility

The native modal setup dialog traps focus, labels every field, validates explicit sphere dimensions and permits Escape/cancel. On cancellation, focus returns to the shared New action. The nonmodal overlay toolbar focuses its heading on opening and returns focus to its toggle on closing. The map keeps the full viewport and proportions throughout. Tool selection moves between the floating row and the open panel without duplicating controls. Contextual panels preserve planar map-unit radius versus spherical meter radius. Shared shortcuts respect text-field Undo. The optional Fullscreen API targets the same root across all shapes; exit/failure leaves the document untouched.

## Planned conversion and geometry

[Issue #2](https://github.com/Revty79/serrian-tide-world/issues/2) defines the permanent unified workspace and future conversion requirement. Conversion must be optional, configurable, previewable, cancelable and non-destructive. It needs a new output identity with traceable origin and an unchanged source. Approved contracts must cover physical dimensions/units, topology, seams/cuts, poles/caps, face connectivity, surface choice, resolution, distortion, detail loss and incompatible regions. Arbitrary texture wrapping is not an accurate general conversion. **No conversion is implemented in F1.**

A6-D2-R supplies held-stroke rotation at the actual globe limb. Its pure camera helper, immutable queued visibility planes and numerical dab interpolation remain separate from the shared host and persistence. The contextual checkbox overlays the map in the existing tools panel; it introduces no permanent panel. See [editing](SPHERICAL-EDITING.md) and [D2-R evidence](A6-D2-R-COMPLETION.md). P1 hardens rendering while retaining that workflow. The owner superseded the separate replacement-Worlds plan: fully interconnected Atlas maps must work before Phase 7 isolated-development integration into existing Worlds; Phase 8 adds bidirectional records, Phase 9 connects existing living history/alternate timelines, Phase 10 verifies acceptance/compatibility/permissions before authorized rollout, and Phase 11 supplies reusable Earth. Preserve existing information and functionality wherever practical. The complete shape/cartography/scale/measurement/3D/history inventory, [Issue #1](https://github.com/Revty79/serrian-tide-world/issues/1) and GPU-free hosting requirements remain in the [master roadmap](PHASE-1-HEIGHTMAP-ROADMAP.md). The live application, databases, authentication and backend services remain untouched. Stop after A7-D for independent review and owner hands-on acceptance. No subsequent geometry phase is authorized.

## Verification approach

The retained A0–A6-E engine and browser assertions continue. Product-entry planar and spherical persistence tests now use the shared creation/library controls. Five retired preview/overlay launcher cases run against a clearly named test-only frozen A6-E host: those historical tests assert preserving an inactive planar editor, a behavior intentionally absent from the new product. Their numerical/visual/interaction assertions were not deleted. New unified product tests replace that hosting assumption with direct shape creation, one active canvas, exact mixed Save/Open, every tool in every view, exact history, cancellation/recovery and desktop/mobile/ultrawide/square/fullscreen evidence. Completion results and exact file/preservation lists are in the F1 completion report and receipt.

## A7-D cylinder provider and saved state

Physical capped cylinder is available directly at `/` through the normal creation dialog. Radius and axial length are explicit meters; detail is 64/128/256 only. The normal host reuses the A7-C physical/connected viewport and exact stroke/history adapter; the development route remains diagnostic. Shared Save/Open, naming, mixed library, shortcuts, fullscreen and overlay tools apply equally to cylinders. The v4 codec preserves all identity/geometry/ownership and exact Float32 words. A sparse exact checkpoint tracks saved content independently of revision and history eviction; fresh reopening has a clean checkpoint and empty session history. Accepted input drains before persistence, failed writes leave both stores and edits intact, and successful replacement disposes the old editor/cache/input work. See [v4 specification and limits](CYLINDRICAL-PERSISTENCE.md) and [A7-D results](A7-D-COMPLETION.md).
